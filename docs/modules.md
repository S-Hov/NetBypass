# Сервисные модули

Каждый сервис хранится в отдельном JSON-файле:

```text
src/NetBypass.App/Profiles/<id>.json
```

Это позволяет независимо включать сервисы, обновлять их домены и постепенно
добавлять relay-кандидаты для автоматического выбора рабочего адреса.

## Формат

```json
{
  "schemaVersion": 1,
  "id": "openai",
  "name": "OpenAI / ChatGPT",
  "category": "AI",
  "default": false,
  "strategies": ["adaptive-hosts"],
  "hosts": [
    {
      "address": "45.155.204.190",
      "hostname": "chatgpt.com"
    },
    {
      "address": "45.155.204.190",
      "hostname": "api.openai.com"
    }
  ],
  "healthChecks": [
    {
      "targetAddress": "45.155.204.190",
      "host": "chatgpt.com",
      "port": 443,
      "protocol": "https"
    }
  ],
  "relayCandidates": []
}
```

Обязательные поля:

- `schemaVersion` — версия формата, сейчас `1`;
- `id` — уникальный стабильный идентификатор;
- `name` — название в интерфейсе;
- `category` — группа на странице сервисов;
- `hosts` — записи, которые можно применить в текущем `hosts`-режиме.

Поле `default` поддерживается форматом, но текущий интерфейс также использует
собственный список модулей, отключённых при первом запуске.

Поле `healthChecks` описывает, какой адрес проверять через TCP/TLS/HTTP.
Если оно отсутствует, NetBypass создаёт проверки автоматически по уникальным
адресам из `hosts`.

Поле `relayCandidates` пока может быть пустым. Оно зарезервировано для
следующей части Adaptive Hosts, где сервис сможет хранить несколько кандидатов
релея.

## Legacy-формат

Старые файлы остаются рядом:

```text
src/NetBypass.App/Modules/<id>.hosts
```

Если каталог `Profiles` пустой или отсутствует, загрузчик использует `.hosts`
как запасной источник. Это нужно только на время перехода.

## Проверка безопасности

Загрузчик отклоняет:

- `0.0.0.0`;
- loopback-адреса;
- private- и link-local-адреса;
- multicast-адреса;
- `localhost` и поддомены `.localhost`;
- строки без корректной пары `IP домен`.

Большие рекламные и вредоносные блок-листы не относятся к задаче NetBypass и
не должны добавляться в сервисные модули.

## Добавление сервиса

1. Создайте отдельный JSON-файл в `Profiles`.
2. Укажите уникальный `id`, понятное имя и категорию.
3. Добавьте только необходимые домены в `hosts`.
4. Проверьте источник и владельца IP-адресов.
5. Выполните `dotnet test`.

Не объединяйте несвязанные сервисы в один модуль без технической необходимости.
