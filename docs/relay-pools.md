# Резервные адреса и relay-пулы

Relay-пулы нужны как запасной источник кандидатов, если адреса из профиля
сервиса не проходят проверку.

Текущая заготовка:

```text
src/NetBypass.App/RelayPools/shared-global.csv
```

Файл пока не используется автоматически. Это небольшой общий список кандидатов,
собранный из уже существующих JSON-профилей NetBypass.

## Почему не добавляем случайные IP из интернета

IP-адрес подходит сервису только если он проходит проверку именно с доменом
этого сервиса:

1. TCP-подключение открывается;
2. TLS handshake проходит с правильным SNI;
3. сертификат соответствует домену;
4. HTTP-ответ не ломает базовую доступность.

Публичные диапазоны CDN и облаков полезны как справочная информация, но не как
готовые строки для `hosts`. Например:

- Cloudflare публикует IPv4-диапазоны на `https://www.cloudflare.com/ips-v4`;
- Fastly публикует публичный список на `https://api.fastly.com/public-ip-list`;
- AWS публикует диапазоны на `https://ip-ranges.amazonaws.com/ip-ranges.json`.

Из этих источников нельзя безопасно взять произвольный IP и назначить его
любому сервису. Сначала нужен сервис-специфичный TCP/TLS-аудит.
